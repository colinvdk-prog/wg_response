## Method

- **Perimeter time series:** NIFC ArcGIS `WFIGS_Daily_Perimeters_Public` FeatureServer layer 0 — researched live: unlike the `_Current` / `_YearToDate` / `InterAgencyFirePerimeterHistory` layers (one latest/final polygon per fire), the Daily layer keeps every published capture as its own row keyed by `poly_PolygonDateTime` (up to 110 rows per IRWIN id measured). Public domain (NIFC open data), keyless.
- **Observed weather:** Open-Meteo HISTORICAL archive (`archive-api.open-meteo.com`, ERA5-family reanalysis) hourly at the fire centroid, wind in m/s, UTC. **Licensing:** free tier is NON-COMMERCIAL and data is CC-BY-4.0 — this harness is an offline R&D calibration study; production use requires the paid tier or self-hosting (same posture as `wgresponse.weather`).
- **Terrain/fuel:** live LANDFIRE LFPS tiles (LF2024_FBFM40 + LF2020 slope/aspect/elev) through the engine's own `terrain.LfpsTerrain`, disk-cached. LF2024 fuels predate the replayed fires (pre-fire landscape — correct for hindcasting).
- **Replay:** for each consecutive snapshot pair (T0, T1): seed `spread.ensemble_arrival` with the T0 rings via the production perimeter-interior path (rings subsampled to <= 200 vertices, `perimeter_at_s = t0 = T0`, no exterior seeds), shipped default `ResponseConfig` (ensemble_n=6, wind_perturb_frac=0.25, moisture_perturb_frac=0.2, dir_perturb_deg=30.0, spotting=OFF), observed weather as the forecast.
- **Scoring under censoring:** a perimeter pair only brackets each newly-burned cell's true burn time inside (T0, T1], so coverage is a CERTAIN/POSSIBLE **bound pair**: certain = band [p10,p90] contains all of [T0,T1]; possible = band intersects it. `late_miss` = p10 > T1 (band entirely after the window — the dangerous, missed-alert polarity), `early_miss` = p90 < T0. STRUCTURAL NOTE: because the window opens exactly at the seed time and no member can arrive before the seed, `p10 <= T0` (and hence the certain bound and the 'sufficient' p10 column) is ~0 BY CONSTRUCTION — those columns are kept for schema honesty but carry no information; the informative statistics are the possible bound, the necessary p10 bound (p10 <= T1), late/early misses, and the PIT histogram (approximated at the window midpoint). Cells whose LANDFIRE code is non-burnable (urban etc.) can never receive a modeled arrival — they are counted and reported, never silently dropped.
- **Head run:** farthest newly-burned boundary cell from the T0 boundary (straight-line, metric grid), observed vs the modeled p50/p10 burned region at T1. Boundary sets are strided to caps, so both numbers are conservative floors (same bias both sides of the ratio).

## DO NOT SHIP A FUDGE

No ROS multiplier, perturbation widening, or quantile remap may ship from
this document alone. The firerisk honest-numbers discipline applies:

- The replay sample here is small (a handful of incidents, interval-censored
  observation windows, one fire season, one state) and the landmark anchors
  are two hand-parameterized scenarios. That is EVIDENCE OF DIRECTION, not a
  calibration fit.
- Any proposed `ResponseConfig` change must first be re-run through this
  harness on an EXPANDED incident set (>= 10 incidents, multiple fuel
  regimes, both wind-driven and terrain-driven fires) and show coverage
  moving toward the target WITHOUT wrecking the early-miss side (a p10 that
  is pessimistic-everywhere is a false-alarm machine that erodes crew trust
  and burns dispatch capacity).
- A grass-ROS ADJ multiplier additionally needs the spotting decision made
  first (F3: spotting is the mechanism that made Camp/Tubbs beat every
  no-spotting model) — tuning surface ROS to absorb missing spotting physics
  bakes ember transport into grass parameters where it does not belong.
- Per SAFETY SEMANTICS, any change lands as config + regression pins, with
  before/after coverage tables appended here, and byte-identity pins
  re-baselined explicitly — never silently.
